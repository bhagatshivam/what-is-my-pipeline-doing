This document provides an overview of the `build-and-test` CI/CD pipeline, detailing its triggers, execution flow, dependencies, and configuration.

### Overview

The `build-and-test` pipeline, defined in `/home/user/what-is-my-pipeline-doing/evaluation/held_out_workflows/nextjs_build_and_test.yml` as a GitHub Actions workflow, is designed to build and test the project.

It manages concurrency by grouping runs based on the event type (pull request or push) and the workflow/ref name or SHA, canceling any in-progress runs within the same group.

This pipeline consists of 40 jobs in total. Five of these jobs have no declared dependencies and run independently, while the remaining 35 jobs depend on the completion of other jobs. A significant portion of the pipeline, 17 jobs, utilizes a build matrix. Among these, 11 jobs define 47 specific combinations for their matrices, with an additional 6 jobs also using matrices whose sizes are not included in that total.

### When It Runs

This workflow is configured to run automatically under the following conditions:

*   On every push to the `canary` branch.
*   On every pull request event.

### What Happens

The `build-and-test` pipeline executes a series of jobs, some independently and others in a dependent sequence. Many jobs delegate their execution to reusable workflows, primarily `build_reusable.yml`, `pr_stack_optimizer.yml`, and `test-turbopack-rust-bench-test.yml`.

Here is a detailed breakdown of each job:

1.  **optimize-ci**: This job delegates its execution to the reusable workflow `/.github/workflows/pr_stack_optimizer.yml`. It runs independently.
2.  **changes**: This job runs independently on `ubuntu-latest` and includes 3 steps: checking out the repository, checking for documentation-only changes, and checking for a release. It requires `contents: read` permissions.
3.  **pr-ci-metadata**: This job runs independently on `ubuntu-latest` and is conditional on the event being a `pull_request`. It has 2 steps: writing PR metadata and uploading that metadata as an artifact using `actions/upload-artifact`. It requires `contents: read` permissions.
4.  **build-next**: This job delegates to the reusable workflow `/.github/workflows/build_reusable.yml` with `needsPlaywright: no`, `skipNativeBuild: yes`, and `stepName: build-next`. It runs independently.
5.  **validate-docs-links**: This job runs independently on `ubuntu-latest` and consists of 4 steps: checking out the repository, setting up Node.js, setting up corepack, and running a link checker.
6.  **build-native**: This job runs after `changes`. It delegates to `/.github/workflows/build_reusable.yml` with `skipInstallBuild: yes`, `stepName: build-native`, and `uploadNativeArtifact: true`. It only runs if the `docs-only` output from the `changes` job is `false`.
7.  **build-native-windows**: This job runs after `changes`. It delegates to `/.github/workflows/build_reusable.yml` with `skipInstallBuild: yes`, `stepName: build-native-windows`, `runs_on_labels: ["windows-latest-8-core-oss"]`, and `uploadNativeArtifact: true`. It only runs if the `docs-only` output from the `changes` job is `false`.
8.  **fetch-test-timings**: This job runs after `changes`. It only runs if the `docs-only` output from the `changes` job is `false`.

### Secrets & Configuration

The pipeline utilizes several environment variables and requires specific secrets for its operations:

**Environment Variables:**

*   `NODE_MAINTENANCE_VERSION`: Set to `20`.
*   `NODE_LTS_VERSION`: Set to `22`.
*   `PR_NUMBER`: Dynamically set to `github.event.pull_request.number` (used in `pr-ci-metadata`).
*   `PR_HEAD_SHA`: Dynamically set to `github.event.pull_request.head.sha` (used in `pr-ci-metadata`).
*   `PR_HEAD_REF`: Dynamically set to `github.event.pull_request.head.ref` (used in `pr-ci-metadata`).
*   `PR_HEAD_REPO`: Dynamically set to `github.event.pull_request.head.repo.full_name` (used in `pr-ci-metadata`).
*   `PR_BASE_REF`: Dynamically set to `github.event.pull_request.base.ref` (used in `pr-ci-metadata`).
*   `PR_IS_FORK`: Dynamically set based on whether `github.event.pull_request.head.repo.full_name` is different from `github.repository` (used in `pr-ci-metadata`).
*   `KV_REST_API_URL`: Populated from the `KV_REST_API_URL` secret (used in `fetch-test-timings`).
*   `KV_REST_API_TOKEN`: Populated from the `KV_REST_API_TOKEN` secret (used in `fetch-test-timings`).
*   `GITHUB_TOKEN`: Populated from the `GITHUB_TOKEN` secret (used in `validate-docs-links`).

**Secrets Required:**

*   `KV_REST_API_URL`: Required by the `fetch-test-timings` job for its "Fetch test timings" step.
*   `KV_REST_API_TOKEN`: Required by the `fetch-test-timings` job for its "Fetch test timings" step.
*   `GITHUB_TOKEN`: Required by the `validate-docs-links` job for its "Run link checker" step.
