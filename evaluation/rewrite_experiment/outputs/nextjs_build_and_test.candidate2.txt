This document provides a walkthrough of the `build-and-test` CI/CD pipeline, designed to help you understand its structure, triggers, and execution flow.

### Pipeline Overview

The `build-and-test` pipeline, defined in `/home/user/what-is-my-pipeline-doing/evaluation/held_out_workflows/nextjs_build_and_test.yml` (a GitHub Actions workflow), manages continuous integration for the project. It is configured to run with a concurrency group that cancels in-progress runs, ensuring only the latest relevant execution proceeds. The concurrency group is dynamically named based on whether the event is a pull request or a push.

This workflow consists of 40 jobs in total. Five of these jobs have no declared dependencies and run independently, while the remaining 35 jobs depend on the successful completion of other jobs. A significant portion of the pipeline, 17 out of 40 jobs, utilizes a build matrix. Among these, 11 jobs define 47 specific combinations, with 6 additional jobs also using matrices whose sizes are not included in that total.

### When the Pipeline Runs

The `build-and-test` pipeline is triggered in two scenarios:
*   On every push to the `canary` branch.
*   On every pull request.

### Initial Setup and Pre-processing Jobs

Several jobs run early in the pipeline to set up the environment, gather metadata, or determine subsequent execution paths:

*   **`optimize-ci`**: This job delegates its execution to the reusable workflow located at `./.github/workflows/pr_stack_optimizer.yml`.
*   **`changes`**: Running on `ubuntu-latest`, this job has 3 steps. It checks out the repository, then specifically checks for "docs only" changes and "release" changes. It requires `contents: read` permissions. This job outputs `docs-only` and `rspack` values, which are used in conditions for other jobs.
*   **`pr-ci-metadata`**: This job runs exclusively on `pull_request` events on `ubuntu-latest` with `contents: read` permissions. It has 2 steps: "Write PR metadata" and "Upload PR metadata" using `actions/upload-artifact`. It utilizes several environment variables to capture pull request details: `PR_NUMBER`, `PR_HEAD_SHA`, `PR_HEAD_REF`, `PR_HEAD_REPO`, `PR_BASE_REF`, and `PR_IS_FORK`.
*   **`fetch-test-timings`**: This job runs on `ubuntu-latest` and depends on the `changes` job. It proceeds only if `needs.changes.outputs.docs-only` is `false`. It involves 9 steps, including setting up Node.js and pnpm, checking out the repository, caching the pnpm store, installing dependencies, fetching test timings, ensuring the timings file exists, and uploading test timings using `actions/upload-artifact`. This job requires the `KV_REST_API_URL` and `KV_REST_API_TOKEN` secrets.

### Core Build Jobs

These jobs are responsible for building various components of the project:

*   **`build-next`**: This job delegates to the reusable workflow `./.github/workflows/build_reusable.yml` with `needsPlaywright: no`, `skipNativeBuild: yes`, and `stepName: build-next`.
*   **`build-native`**: This job delegates to `./.github/workflows/build_reusable.yml` with `skipInstallBuild: yes`, `stepName: build-native`, and `uploadNativeArtifact: true`. It runs after the `changes` job and is conditional on `needs.changes.outputs.docs-only` being `false`.
*   **`build-native-windows`**: Similar to `build-native`, this job delegates to `./.github/workflows/build_reusable.yml` with `skipInstallBuild: yes`, `stepName: build-native-windows`, `runs_on_labels: ["windows-latest-8-core-oss"]`, and `uploadNativeArtifact: true`. It also runs after `changes` and is conditional on `needs.changes.outputs.docs-only` being `false`.

### Linting and Static Analysis

These jobs ensure code quality and documentation integrity:

*   **`lint`**: This job delegates to `./.github/workflows/build_reusable.yml` with `needsPlaywright: no`, `skipNativeBuild: yes`, `skipNativeInstall: yes`, and `stepName: lint`. It executes `pnpm lint-no-typescript` (and 7 more lines of commands) after the `build-next` job.
*   **`validate-docs-links`**: Running on `ubuntu-latest`, this job has 4 steps: checking out the repository, setting up Node.js, setting up corepack, and running a link checker. It requires the `GITHUB_TOKEN` secret.
*   **`ast-grep`**: This job runs on `ubuntu-latest` after the `changes` and `build-next` jobs. It has 2 steps: checking out the repository and running an `ast-grep lint` step using `ast-grep/action`.
*   **`check-types-precompiled`**: This job delegates to `./.github/workflows/build_reusable.yml` with `needsPlaywright: no`, `afterBuild: pnpm types-and-precompiled`, and `stepName: types-and-precompiled`. It runs after the `changes`, `build-native`, and `build-next` jobs.

### Environment Variables and Secrets

The pipeline uses several environment variables and requires specific secrets:

#### Environment Variables
*   `NODE_MAINTENANCE_VERSION`: Set to `20`.
*   `NODE_LTS_VERSION`: Set to `22`.
*   `PR_NUMBER`: Set to `${{ github.event.pull_request.number }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.
*   `PR_HEAD_SHA`: Set to `${{ github.event.pull_request.head.sha }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.
*   `PR_HEAD_REF`: Set to `${{ github.event.pull_request.head.ref }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.
*   `PR_HEAD_REPO`: Set to `${{ github.event.pull_request.head.repo.full_name }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.
*   `PR_BASE_REF`: Set to `${{ github.event.pull_request.base.ref }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.
*   `PR_IS_FORK`: Set to `${{ github.event.pull_request.head.repo.full_name != github.repository }}`, used in the `pr-ci-metadata` job's "Write PR metadata" step.

#### Secrets Required

*   `KV_REST_API_TOKEN`: Used in the `fetch-test-timings` job's "Fetch test timings" step.
*   `GITHUB_TOKEN`: Used in the `validate-docs-links` job's "Run link checker" step.
