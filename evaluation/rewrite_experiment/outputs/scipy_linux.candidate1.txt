This document provides an overview of the "Linux tests" CI/CD pipeline, detailing its triggers, execution flow, and configuration.

### Overview

The "Linux tests" pipeline is a GitHub Actions workflow defined in `/home/user/what-is-my-pipeline-doing/evaluation/held_out_workflows/scipy_linux.yml`. It requires `contents: read` permissions. To manage concurrent runs, it groups workflows by `${{ github.workflow }}-${{ github.head_ref || github.run_id }}` and cancels any in-progress runs within the same group.

This pipeline consists of 12 jobs. One job runs independently, while the remaining 11 jobs depend on other jobs. Three of the 12 jobs utilize a build matrix; two of these define a total of 3 configured combinations, with the matrix size of one additional job not included in this total.

### When It Runs

This workflow is triggered automatically in the following scenarios:

*   On every push to the `main` branch or any branch matching the `maintenance/**` pattern.
*   On every pull request that targets the `main` branch or any branch matching the `maintenance/**` pattern.

### What Happens

The pipeline executes 12 jobs. The `get_commit_message` job runs first, independently of any other jobs. All other jobs depend on `get_commit_message` and will only run after it completes successfully.

Here is a detailed breakdown of each job:

1.  **get_commit_message**: This job delegates its execution to a reusable workflow located at `./.github/workflows/commit_message.yml`.
2.  **test_meson**: This job runs on `ubuntu-22.04` and consists of 15 steps. It uses a build matrix that can generate up to 2 combinations based on `python-version` and `maintenance-branch`, with 1 combination explicitly excluded. It runs after `get_commit_message` and only if `needs.get_commit_message.outputs.message` is `1` and the repository is `scipy/scipy` or an empty string. Its steps include:
    *   `actions/checkout`
    *   `Setup Python`
    *   `Install Ubuntu dependencies`
    *   `Install Python packages`
    *   `Install Python packages from repositories`
    *   `Set up ccache`
    *   `Setup build and install scipy`
    *   `Ccache performance`
    *   `Check installed files`
    *   `Check symbol hiding`
    *   ... and 5 more steps.
3.  **test_venv_install**: This job runs on `ubuntu-24.04` and has 7 steps. It runs after `get_commit_message` and only if `needs.get_commit_message.outputs.message` is `1` and the repository is `scipy/scipy` or an empty string. Its steps include:

### Dependencies

This workflow calls the reusable workflow located at `./.github/workflows/commit_message.yml`.

### Secrets & Configuration

The pipeline utilizes the following environment variables for configuration:

*   `CCACHE_DIR`: Set to `${{ github.workspace }}/.ccache`
*   `CCACHE_MAXSIZE`: Set to `250M`
*   `CCACHE_COMPILERCHECK`: Set to `content`
