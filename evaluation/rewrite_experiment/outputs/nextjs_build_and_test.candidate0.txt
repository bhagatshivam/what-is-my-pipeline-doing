The `build-and-test` pipeline, defined in `nextjs_build_and_test.yml` for GitHub Actions, runs on every push to the `canary` branch and on every pull request. It manages concurrency by canceling in-progress runs within a group determined by the event type and reference. This pipeline consists of 40 jobs, with 5 running independently and 35 depending on other jobs. Many jobs utilize a build matrix, with 11 jobs defining 47 specific combinations.

The pipeline begins with several independent jobs: `optimize-ci` delegates to a reusable workflow for stack optimization; `changes` checks for documentation-only modifications and release status; `pr-ci-metadata` writes and uploads pull request metadata specifically for pull request events; `build-next` builds Next.js; and `validate-docs-links` checks documentation links. Following these, `build-native` and `build-native-windows` build native components, conditional on changes not being docs-only. `fetch-test-timings` then sets up Node.js and pnpm, caches dependencies, fetches, and uploads test timings.

A wide array of tests and quality checks are performed. These include `lint` and `ast-grep` for code quality, `check-types-precompiled` for type validation, and `test-cargo-unit`, `rust-check`, and `rustdoc-check` for Rust-related components. The pipeline executes various test suites such as `test-bench`, `devlow-bench`, `test-devlow`, `test-turbopack-dev`, `test-turbopack-production`, `test-rspack-dev`, `test-rspack-production`, `test-next-swc-wasm`, `test-next-napi-bindings-wasi`, `test-unit`, `test-next-config-ts-native-ts-dev`, `test-next-config-ts-native-ts-prod`, `test-new-tests-dev`, `test-new-tests-start`, `test-dev`, `test-prod`, `test-firefox-safari`, `test-cache-components-dev`, `test-cache-components-prod`, `test-new-tests-deploy`, and `test-new-tests-deploy-cache-components`. Several of these tests also have dedicated Windows variants, including `test-unit-windows`, `test-dev-windows`, `test-integration-windows`, and `test-prod-windows`. Most of these jobs delegate to reusable workflows and are conditioned on previous job outputs and event types.

The final job, `tests-pass`, runs after nearly all other jobs have completed and includes a step that exits with code 1. This pipeline requires the `KV_REST_API_URL` and `KV_REST_API_TOKEN` secrets for fetching test timings, and the `GITHUB_TOKEN` secret for running the documentation link checker. Additionally, it utilizes environment variables such as `NODE_MAINTENANCE_VERSION`, `NODE_LTS_VERSION`, and various `PR_` prefixed variables for pull request metadata.
